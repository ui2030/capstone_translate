# bench — 합격선 자동 채점판

"이 프로젝트가 끝났는가"를 사람 판단 없이 숫자로 답하는 도구.
합격선 6개(HANDOFF_NEXT.md §3)의 판정은 **여기서만** 나온다. 눈으로 보고 "좋아진 것 같다"는 인정하지 않는다.

```
python bench/score.py              # 전 항목 (실측 약 167초 — 2026-09-07 폰트 축 시료 13장 추가로 +5초)
python bench/score.py --only 1,4   # 일부만
python bench/score.py --reps 20    # 기준 4: 자막/채팅이 각각 바뀌는 횟수 (기본 10)
python bench/make_fixtures.py      # 시료 + 정답 재생성
```

파이썬은 반드시 `C:\Users\ui2030\anaconda3\envs\cd\python.exe`.

## 폴더

|---|---|---|

## 시료

정답 텍스트가 이 프로젝트의 핵심 자산이다. **정답은 받아쓴 것이 아니라 "그린 문자열 그대로"** —
`make_fixtures.py` 가 이미지를 그리면서 같은 문자열을 `truth/*.json` 에 적는다. 그래서 시료와 정답이
어긋날 수 없다. 폰트는 실제 Windows 폰트(Segoe UI / Malgun Gothic / Microsoft YaHei / Segoe Fluent
Icons), 크기는 실제 UI 크기(10~24px)를 쓴다.

### 규칙 — 시료를 추가할 때는 **그 시료가 대표하는 축을 먼저 적는다**

축 = 폰트 / 크기 / 굵기 / 배경 / 렌더방식. 축을 안 적고 시료를 늘리면 같은 조건이 여러 장으로
불어날 뿐이고, 그러면 **시료가 앱을 봐준다**. 2026-09-07에 실제로 그랬다 — 기준 1의 채점 대상
10장이 전부 `Segoe UI Regular · 흰 배경 · 같은 문장 1개`여서 CER 0% 만점이 나왔는데,
폰트만 바꾸자 최악 100%가 나왔다. 아래 표의 "대표하는 축" 칸을 비운 채 시료를 추가하지 마라.

`screen_*` 를 따로 둔 이유: PIL 렌더는 회색조 안티에일리어싱이라 실물보다 깨끗하다.
합성 시료만 쓰면 10px에서 오류율 0%가 나와 **시료가 앱을 봐주게 된다**.

**폰트 축이 크기 축보다 지배적이다**(2026-09-07 실측 448건): Segoe UI만 쓰면 10px 최악 3.2%인데
폰트를 바꾸면 최악 100% · CER>5% 비율 37%. 배경 축은 반대로 거의 영향이 없다(0.4~3.2%p) —
그래서 배경은 `comic_*` 두 장만 두고 늘리지 않는다.

### 시료 추가하는 법

0. **이 시료가 어떤 축을 대표하는가**를 한 줄로 쓴다. 위 표에 행을 먼저 추가하고,
   같은 문장을 `make_fixtures.py` 의 `notes=` 에도 남긴다(정답 JSON에 그대로 들어간다).
   기존 축을 한 번 더 찍는 시료라면 **추가하지 않는다** — 채점만 느려진다.
1. `make_fixtures.py` 에 `make_xxx()` 를 추가한다. `Sheet.para()` / `Sheet.line()` 으로 그리면
   그린 문자열이 자동으로 정답 문단이 된다(`truth=False` 로 정답에서 뺄 수 있다).
   폰트·굵기 축만 바꾸는 시료라면 함수를 새로 쓰지 말고 `FONT_AXIS` / `SCREEN_AXIS` 표에
   한 줄 추가하면 된다.
2. `save(name, lang=..., font_px=..., expect_display=..., role=..., notes=...)`.
   - `expect_display=False` → "자막이 뜨면 안 되는 화면"(기준 2의 오표시 검출).
   - `s.forbidden.append(...)` → "이 문자열이 번역돼 뜨면 사고"(병음 등).
3. `python bench/make_fixtures.py` 로 png + json 재생성.
   폰트가 없는 PC에서는 **조용히 대체하지 않고 그 시료를 건너뛴 뒤 목록을 찍고 종료코드 1**로 끝난다
   (PIL은 파일 경로 존재 확인, Qt는 `QFontInfo` 로 실제 매칭된 폰트 이름을 대조한다.
   Qt는 없는 폰트를 말없이 바꿔치기하므로 이 대조가 없으면 시료와 정답이 어긋난다).
4. 기준 3의 채점 대상(graded)에 넣으려면 `score.py` 의 `criterion3()` 안 `graded` 조건에 이름을 추가.
   기준 4는 시료 PNG를 쓰지 않는다 — 화면에 직접 그린다(`_latency_probe` 의 `LAT_LINES`).
5. **기준 1 채점 대상은 이름이 `size_`/`screen_` 으로 시작하고 `font_px` 가 14 이하인 시료다**
   (`criterion1()`). 11px 같은 값은 표에는 나오지만 판정에 안 들어간다 — 이름과 px를 그에 맞춰라.

**이미지에 그렸지만 정답에 없는 글자를 만들지 마라.** 채점기는 정답에 없는 텍스트를 전부 삽입 오류로 센다
(아이콘 글리프는 의도적으로 그 함정으로 남겨 뒀다 — 아이콘을 글자로 읽으면 점수가 떨어져야 맞다).

## 채점 방식 (무엇을 정확히 재고, 무엇을 대리 지표로 재는가)

- **앱의 진짜 함수만 부른다**: `BackgroundController.perform_ocr_with_boxes` →
  `assign_region_languages` → `batch_translate` → `display_gate_reject`.
  워커 루프와 같은 순서다. 재구현한 로직은 하나도 없다.
- **기준 1 — 정확히 잰다.** 페이지 단위 문자 오류율(CER, 편집거리/정답 길이). 판정은 14px 이하 전부(값을 열거하면 11px 같은 중간 크기가 사각지대가 된다 — 실제로 그랬다).
- **기준 2 — 반은 정확, 반은 대리 지표.**
  - 정확: 오탐률 = (정답 문장을 제대로 읽었는데 게이트가 숨긴 줄) / (제대로 읽은 줄). 이 프로젝트가
    CO-2 사건으로 크게 데인 지표라 반드시 정확히 잰다. 분모·분자를 `last_score.json` 에 그대로 남긴다.
  - 정확: 한국어 화면 오표시 건수, 병음이 문장으로 번역된 건수(뜬 것/게이트에 걸린 것 분리).
  - **대리 지표**(자동 판정 불가): 미번역 잔류·목표 언어 글자 비율·길이 붕괴. "뜻이 뒤집혔는가"는
    기계가 못 본다. 그래서 표본을 `last_samples.md` 로 뽑아 사람이 읽게 한다.
- **기준 3 — 정확히 잰다.** 정답 문단에만 등장하는 "판별 토큰"의 분포로 잘못 합침/쪼갬을 센다.
  정답 문단의 절반도 못 읽은 화면은 `인식실패로 측정불가` 로 표시한다 — 못 읽은 걸 "경계 오류 0건"이라고
  쓰면 그게 거짓말이다.
- **기준 4 — "화면 변화 → 자막"을 실제 앱으로 잰다** (2026-09-07 재정의, errors.md BM-1).
  예전에는 **한 사이클 시간**(캡처+OCR+번역)만 재서 폴 간격과 "앞 사이클을 기다린 시간"이
  빠져 있었다 — 그래서 채점은 통과인데 사용자는 2~3초를 느꼈다.
  이제 별도 프로세스(`--_latency_probe`)에서 진짜 앱(설정창 + 워커 + 오버레이)을 띄우고,
  화면의 글자를 바꾼 시각 t0 과 그 번역이 오버레이 `paintEvent` 에 그려진 시각 t1 을 잰다.
  오버레이는 `WDA_EXCLUDEFROMCAPTURE` 라 스크린샷으로는 안 잡히므로 `paintEvent` 훅이 유일한 길이다.
  - 시나리오 3종: **자막**(배경 고정 + 아래 한 줄만 새 문장으로 교체) /
    **채팅**(새 줄이 붙고 목록 전체가 위로 밀림 = 변경 밴드 무효, 매번 전체 OCR) /
    **정적 문서**(한 장을 한 번 띄움). 문장은 전부 서로 달라 **번역 캐시가 절대 안 듣는다**.
  - 판정은 세 시나리오를 합친 p50/p95. **자막이 아예 안 뜬 것(`missed`)이 하나라도 있으면 실패** —
    덜 띄워서 빨라지는 것은 개선이 아니다.
  - 환경에 오염된다. 측정 전 `nvidia-smi`/`psutil` 로 재고 임계(GPU 25% / CPU 30% / VRAM 3GB)를
    넘으면 경고 + 결과에 기록한다.
- **기준 5·6 — 자동으로 다 못 잰다.** 자동으로 재는 것만 재고 나머지는 체크리스트로 출력한다.
  - 자동: 설정창을 4가지 크기 × (기본 / `QT_FONT_DPI=168`)로 실제로 띄워 ① 창 밖으로 나간 위젯
    ② 위젯보다 글자가 넓어 잘리는 항목을 센다. 트레이 메뉴 항목 수, 단축키, 첫 실행 안내 분기,
    설정창·오버레이 렌더 PNG(오버레이는 `WDA_EXCLUDEFROMCAPTURE`라 `grab()` 아니면 안 잡힌다).
  - 자동(기준 6): **프로세스 시작 → 설정 창이 실제로 보일 때까지의 시간**(≤2.0s).
    앱 밖에서 `FindWindowW`로 폴링한다 — 앱 안에서 재면 "언제부터"를 못 잡는다.
    import 시간은 참고로만 남긴다: 무거운 것을 백그라운드 스레드로 옮기면 import 시간과
    체감이 갈라지고(LZ-1: import 1.05s인데 창 1.25s), 사람이 기다리는 건 창이다.
  - 자동(기준 6): 자가진단과 시작 측정은 **배포물(`dist/Cocktail/Cocktail.exe`)이 있으면
    그것으로** 돌린다. "파이썬 불필요"를 실제로 재는 유일한 방법이다. 배포물 신선도/크기,
    동봉 여부(tesseract 엔진 · tessdata · 번역 모델), exe 아이콘 리소스,
    `torch_imported_at_ui_import`(LZ-1 회귀 가드)도 판정 조건에 들어간다.
  - 수동: 실제 드래그 리사이즈, 175% 보조 모니터, 인스톨러 컴파일(Inno Setup),
    깨끗한 PC 설치, 백신/코드 서명, 5분 준비.

## 함정 (이 도구를 고칠 사람에게)

- `cocktail_ocr` 는 `sys.argv[0]` 폴더의 `tessdata` 를 찾는다. `bench/` 에서 실행하면 프로젝트
  tessdata(10종)를 못 본다 → `score.py` 가 import 전에 `TESSDATA_PREFIX` 를 직접 박는다.
- 엔진은 `from cocktail_ocr import ...` 로 상수를 **복사**해 간다. 레버를 바꿔 재려면
  `cocktail_engine.<상수>` 를 갈아끼워야 한다.
- UI 프로브는 별도 프로세스에서 돌고 `BackgroundController.start` 를 no-op 으로 덮는다
  (모델 로드·워커 스레드·실화면 캡처 금지). QSettings 는 Windows 레지스트리라 격리가 안 돼서,
  저장된 설정은 **읽기만** 하고 첫 실행 안내는 분기만 다시 태운다.
- 영구 캐시(DPAPI)는 `PERSIST_CACHE._enabled = False` 로 꺼 둔다. 켜 두면 사용자의 캐시가
  속도 측정을 오염시키고 벤치 결과가 캐시에 남는다.
- **OCR 결과는 완전히 결정론적이지 않다.** UB-1 확대 배율이 1차 패스의 **실측 시간**으로 정해지기
  때문에, 같은 이미지라도 PC가 바쁘면 배율이 달라져 인식 결과가 달라진다(실측: 같은 zh 시료가
  2줄/3줄로 갈림). 점수가 흔들리면 먼저 이걸 의심하라.

- **기준 4 프로브의 함정**: 자극 화면의 **배경 문장이 시료 문장과 겹치면 안 된다.**
  겹치면 "이미 떠 있던 자막"에 즉시 매칭돼 지연이 0에 가깝게 거짓 계측된다
  (개발 중 실제로 340 ms 가 나왔고 진짜 값은 2.8초였다).
- 프로브는 자기 창을 화면에 띄운다 — 측정 중 다른 창을 앞으로 올리지 마라.
